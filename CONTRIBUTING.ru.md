# Как участвовать

[English](CONTRIBUTING.md) · [Русский](CONTRIBUTING.ru.md)

Исправления и новые вопросы принимаются, если у них есть датированный публичный источник. Сначала прочитайте [методику](docs/ru/METHODOLOGY.md).

## Сообщить о проблеме

Чтобы помочь, не обязательно править YAML. Откройте issue по одной из форм:

- **Предложить вопрос**: сам вопрос, что он проверяет, и датированный публичный источник, где о нём сообщили.
- **Сообщить об ошибке**: у каждого вопроса на странице темы есть ссылка «Предложить правку» — она открывает эту форму с уже заполненным id вопроса.
- **Сообщить об устаревшем источнике**: ссылка не открывается либо изменилось содержание страницы или сам процесс интервью.

Персональные данные или конфиденциальные материалы, попавшие в репозиторий, — это вопрос приватности, а не обычная ошибка: действуйте по [SECURITY.md](SECURITY.md) и не повторяйте их в публичном issue.

## Добавить или исправить материал

1. Добавьте источник в `src/content/sources.yaml`: `id`, `kind`, `title`, `publisher`, `url`, `retrieved` (дата, когда вы его прочитали), `lang`, а также `published`, если дата известна, и `license` для переиспользуемой подборки.
2. Добавьте вопрос в `src/content/questions/<тема>.yaml` или этап в `src/content/companies/<компания>.yaml`. Пишите своими словами и заполняйте и `en`, и `ru`.
3. Честно укажите происхождение. Вопрос `published` ссылается на источник, который о нём сообщает, и на `company`, если источник её называет. Вопрос `generated` ссылается только на `radar:<тема>`. Этап `confirmed` подтверждается только источником компании, `participant_report` — только рассказом от первого лица, `secondary` — гайдом или подборкой, `assumption` ставится, когда источника нет.
4. Связывайте роли там, где это подтверждает источник. Добавьте элементу `evidence` поле `role:`, если источник называет роль, на которую проходило собеседование, а этапу собеседования — `roles:`, если о нём сообщали для определённых ролей; из этого строятся страницы профессий. Собственный список `roles` у вопроса лишь отмечает, что вопрос полезен для практики на эти роли. Вакансия — источник вида `posting`: она описывает роль и никогда не подтверждает вопрос или этап. Тексты о направлениях ролей лежат в `src/content/roles.yaml`.
5. Запустите `uv run python scripts/build.py`, чтобы пересобрать README и страницы. Сгенерированные файлы вручную не правьте.

Берите каждую строку YAML в кавычки, длинный текст пишите в блочном стиле. Даты — строки ISO (`"2026-09-27"`, `"2026-09"` или `"2026"`).

Если URL уже зарегистрирован, используйте существующий ID источника. Свидетельства для повторяющегося вопроса объединяйте в его записи, сохраняя опубликованный ID. Валидация отклоняет повторные URL после удаления завершающих слешей и одинаковые тексты вопросов внутри каждого языка после нормализации регистра и пробелов. Разные фрагменты URL остаются различными; проверка не находит смысловые дубли, поэтому перед добавлением сравните формулировку и охват.

## Что мы не можем принять

- Материалы из-за логина, обхода платного доступа или CAPTCHA, а также скрейпинг вопреки правилам сайта.
- Вопросы от тех, кто пишет, что связан NDA, и любая часть рассказа, автор которого по этой причине не раскрывает вопросы.
- Сайты «гайдов по собеседованиям», сгенерированные по одному шаблону для множества работодателей и приводящие статистику без источника.
- Персональные данные: контакты, приватные пути, ссылки на закрытые каналы, текст резюме и всё, что указывает на кандидата.
- Ответы, которые ведут только на платный курс.

## Проверки

```sh
uv sync
uv run ruff check . && uv run ruff format --check .
uv run pytest -q
uv run python scripts/build.py --check
# если менялись docs/, scripts/ или src/atlas:
uv run --group site mkdocs build --strict -f scripts/mkdocs.yml
```

Мейнтейнеры также запускают проверку перед публикацией: список разрешённых путей, правила содержимого и [Gitleaks](https://github.com/gitleaks/gitleaks), плюс приватный словарь строк, которых здесь быть не должно. Проверку выполняет CLI [Career Copilot](https://github.com/eiler2005/career-copilot), и выкачивать этот проект для неё не нужно:

```sh
git config --local core.hooksPath .githooks
git config --local ajh.privateDictionary /absolute/path/to/privacy-dictionary.json
uvx --from "git+https://github.com/eiler2005/career-copilot@fac2dd3c3545c97b07fdb47fddb717f7db732a60" \
  ajh privacy check --root . --scope worktree --gitleaks
```

Чтобы использовать локальную копию того проекта, укажите её в `ATLAS_PRIVACY_APP`. Хуки повторяют проверку для точного набора застейдженных файлов и для всей истории перед push. Добавляйте в индекс только явные пути и не обходите хуки.

## Ответы

У приоритетного вопроса (`start_here`) может быть написанный ответ:

```yaml
    answer:
      ru: "Один абзац на 100–150 слов."
```

Пишите один абзац, который кандидат мог бы произнести вслух: сначала суть, затем механизм и чем за него платят, затем что бы вы сделали или измерили, и в конце — где ответ перестаёт работать. Он не должен противоречить строке `tests` и чек-листу `outline` из трёх пунктов: ответ — это их связная, устная версия. Опирайтесь на указанное в `reading`; выдуманные числа, бенчмарки и факты о компаниях недопустимы. Стандартные формулы можно.

Для вопросов `behavioral` и `self_presentation` историю писать нельзя. Опишите, как кандидату построить собственный ответ, что на самом деле слушает интервьюер, какая типичная ошибка и чем закончить. Ответ, который читается как готовая байка, не принимается.

Один язык может появиться раньше другого: страницы `answers` и книга ответов для языка создаются, только когда на этом языке есть ответы. Текст — обычный, без Markdown и переносов строк.

## Предпросмотр сайта

Те же страницы можно опубликовать как сайт с поиском, с английским и русским меню; публикация на GitHub Pages выключена, пока её не включит сопровождающий. Сайт собирает MkDocs из `docs/` с настройками из `scripts/mkdocs.yml`; `scripts/mkdocs_hooks.py` строит меню из `src/content` и направляет ссылки, ведущие за пределы `docs/`, на карту атласа или на GitHub, так что меню не нужно поддерживать вручную.

```sh
uv sync --group site
uv run --group site mkdocs serve -f scripts/mkdocs.yml            # http://127.0.0.1:8000/ai-interview-atlas/
uv run --group site mkdocs build --strict -f scripts/mkdocs.yml   # в build/site, как в CI
```

## PDF-книги для печати

Тот же материал можно распечатать — по одной книге на каждый язык. Книги собирает рендерер документов [Career Copilot](https://github.com/eiler2005/career-copilot), версия которого закреплена в `pyproject.toml`, в его стандартной вёрстке: страницы A4, основной текст 12 pt, содержание, закладки PDF и кликабельные ссылки на источники.

```sh
uv sync --group pdf
uv run --group pdf python scripts/build_pdf.py
```

Книги, их Markdown-исходники и манифесты с хешами сохраняются в `dist/pdf/`. Нужен Unicode-шрифт TTF: Arial на macOS, DejaVu Sans в Linux или `--font PATH`. Если в шрифте нет какого-то символа, сборка останавливается. График радара добавляется, если установлен `rsvg-convert`. Прежде чем делиться книгой, проверьте извлечённый текст и просмотрите каждую страницу (`pdftotext`, `pdftoppm`). PDF — файлы для релизов: не добавляйте их в Git.
